# BurstPQS: the ground it builds

Part of [Terrain Precision Fix](../../../README.md), one point of [Work in progress](../../work-in-progress.md), on [BurstPQS](../../work-in-progress/burst-pqs.md).

**Status: planned — read in the source, not measured.** [BurstPQS](https://github.com/Phantomical/BurstPQS)
makes terrain generation faster: it builds the terrain quads in parallel, in Burst-compiled jobs, in
place of the stock code. It requires Kopernicus, and its author also contributes to Parallax Continued.
On a body it cannot handle, it falls back to stock, and this fix then works as it does without it.

Read in the source, release 1.0.27:

- **It builds the vertices itself.** BurstPQS replaces `PQS.BuildQuad` with a prefix that skips the
  stock method, so `PQS.BuildVertexSurfaceRelative`, where this fix places each vertex inside its quad,
  is never called: that patch of this fix does nothing on a body BurstPQS builds. BurstPQS works out the
  position of each vertex relative to its quad in double precision itself (`BuildQuadJob`,
  `BatchPQS.TryGetPlanetToQuad`).
- **It places the quads itself.** While the world turns with the body, which is the case near the
  ground, BurstPQS puts the quads in the same local space storage as stock, at a world position worked
  out in double from the body's own position and rotation (`BatchPQS.PlaceQuad`,
  `BatchPQS.GetPreciseLocalToWorld`), and moves them again from those doubles every time stock updates
  the position of the quads. That is what this fix does to the quads of the highest subdivision level,
  from the same two values. Both act after `PQ.SetupQuad`, in an order neither of them sets. When the
  world does not turn with the body, BurstPQS hangs every quad from the sphere, at its float position
  relative to the centre of the body, and this fix, which only acts on the quads in the storage, leaves
  them as they are.
- **Its changelog names the same defect.** Release 1.0.26: *"Quads generated by BurstPQS will no longer
  be built at different locations depending on the floating origin location. This should reduce cases
  of vessels jumping when loading in, though it will not be fully eliminated."*
- **The rest of this fix is left alone.** BurstPQS has no code for `PQSCity` or `PQSCity2`, so the
  statics fix acts as without it. It still lets stock spawn the scatter once a quad is built
  (`Mod/LandControl.cs`), through the `PQSMod_LandClassScatterQuad.Setup` this fix patches. Both add a
  postfix to `CelestialBody.CBUpdate`, and neither skips the stock method there.

What the source does not say: whether the ground a craft stands on comes back to the same place at
every load with BurstPQS alone, what is left of the *"not fully eliminated"*, and whether this fix
changes anything once BurstPQS has placed the quads.
